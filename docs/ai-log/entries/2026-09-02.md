## Session 3 · Fixture design investigation — interrupted, resumed, salvaged

**Asked.** Decide the Phase 1 fixture substrate for a machine with no `losetup`, no
`mkfs`, no Sleuth Kit and a stopped Docker daemon. Report the decision when it lands.

**Produced.** An eleven-agent investigation. Four probes reported; two were killed
mid-flight at 13:06 by an unrelated interrupt, taking the judges, synthesis and critic
down with them. Resumed from the run id; the four completed probes returned from cache.
Before resuming, the two killed transcripts were mined, because both had finished their
measurements and died during cleanup. Findings recorded here so a third interrupt cannot
cost them again.

**Measured findings worth keeping.**

*The reproducibility landmine.* `zlib.compress` output is a property of the linked libz,
not of the input. Python's `zlib` here links `/usr/lib/libz.1.dylib`. Info-ZIP and zlib
produced 13,937 vs 14,066 bytes from identical input, both decompressing correctly. PNG,
DOCX and GZIP all ride on DEFLATE, so the corpus would have differed per laptop and rule 6
would have failed in a way no single-machine test could detect. uv's managed CPython
bundles sqlite statically but still links the system libz — pinning the interpreter does
not pin zlib. Fix: a 190-line fixed-Huffman DEFLATE encoder, leaving `zlib` for CRC32 and
Adler32 only, which are fixed algorithms. Corpus then verified byte-identical across three
interpreters (Homebrew 3.11.15/sqlite 3.53.4, uv-managed 3.11.16/sqlite 3.53.1 static,
system 3.9.6/sqlite 3.51.0): 40 files, 3,836,484 B, manifest sha256 58af4ead. Validity
checked by external decoders, 36/36 — Apple ImageIO, CoreAudio, Info-ZIP, `gzip -t`.
Entropy span 4.5103 to 7.8764 bits/byte.

*Docker is not required for approach A.* `mke2fs`, `debugfs`, `dumpe2fs` and `e2fsck` were
built natively on macOS arm64, and dosfstools 4.2 was patched into building `mkfs.fat`.
Measured, not cited: `mkfs.fat --invariant -i <id>` is byte-identical across runs and
between 4.2 and master; `SOURCE_DATE_EPOCH` is NOT honoured by released dosfstools 4.2;
`mke2fs -d` is deterministic given fixed file creation order and indifferent to locale,
but changing creation order changes the image.

*Hand-written FAT32 is credible.* 775 lines of stdlib Python produce a 256 MiB image that
Apple's msdos driver mounts read-write and `fsck_msdos` passes clean. Negative control:
rewriting one mid-chain FAT entry makes the fragmented file vanish from the mount, so the
driver is genuinely walking the chosen cluster chains. Five boot-sector corruptions each
produced "no mountable file systems", so the mount test can fail.

*The guard found a real defect in itself.* A red-team row with `/dev/disk0` allowlisted and
the env var set returned EPERM — the guard permitted the write and only lack of root
privilege stopped it. That is precisely the disqualifying defect rule 4 exists to prevent.
36/36 attacks refused after the fix.

**Unsure.**
- **The decision is still not made.** One probe and the entire judge/synthesis/critic stage
  were still running when this was written. Nothing above is a decision; it is evidence.
- **Two independent probes found the image is almost entirely zeros** — 1.43% corpus
  occupancy, 55.3% zero free space. A post-wipe carve over mostly-zero media proves less
  than the demo claims. Phase 1 likely needs deterministic residue filling free space.
  Neither the build pack nor the operator's brief anticipated this.
- The salvaged numbers come from transcripts of killed agents. They are real measurements,
  but the re-run may reach different conclusions and has not been cross-checked yet.
- Nothing from this investigation has been implemented. `fixtures/build_image.py` is still
  a one-line docstring; every prototype lives in the scratchpad and may be discarded.

## Session 5 — three adversarial verifiers attacked the fixture; blocker and majors fixed

**Task.** Fix every blocker and major finding from the reproducibility, forensic-correctness
and acceptance verifiers, without weakening a test or deleting the check that caught the
defect. Rebuild, re-measure, report.

**Fixed.**
- **[major, forensic/acceptance] Deleted files were not "unreferenced data".** Deletion set
  the dirent's first byte to 0xE5 and freed the FAT chain, but the short entry still carried
  `DIR_FstClusHI`, `DIR_FstClusLO` and `DIR_FileSize` — so a metadata reader needed no
  carving. Measured before: TSK `icat` recovered **8 of the 12** deleted files byte-perfect
  from the directory alone (every contiguous one). `fixtures/fat32.py` now zeroes all three
  fields on the short entry only, leaving the LFN chunks — which hold name characters at the
  same offsets — untouched. Measured after: **`icat` recovers 0 of 12, each emitting 0 bytes**,
  while all **28 live files still recover byte-perfect**, all 12 long names still parse, and
  all 12 files' planted bytes are still present in `blkls`'s 263,948,288-byte unallocated
  stream. `test_deleted_entries_carry_no_allocation_fields` asserts it with no TSK dependency,
  paired with `test_live_entries_still_carry_their_allocation_fields` as the control.
- **[major, reproducibility/acceptance] The build exited 0 on drift.** `build_image.py`
  printed `committed sha256 match  NO` and returned success, and `--quiet` — the scripting
  mode — never ran the comparison at all. The comparison is now a function
  (`_compare_expected`) that runs in **both** modes and the exit status carries it: **4** on a
  mismatch, with both hash pairs on stderr. `--no-check-expected` is the typed escape for a
  deliberate change (`make fixtures CHECK=--no-check-expected`). Measured on a drifted clone
  (`DEFAULT_VOLUME_LABEL` "SENTINELWP"→"SENTINELWQ"): `--quiet` exits **4**, `make fixtures`
  exits **2** (make's own recipe-failure code), `CHECK=--no-check-expected` exits 0. The chain
  to `make` is closed; it no longer needs the Phase-2 `make test` stub.
- **[major, reproducibility] The rule-1/rule-5 lint was a regex and an alias walked through it.**
  `import zlib as _z; _z.compress(...)`, `from zlib import compress; compress(...)` and 14 of
  17 clock/entropy spellings passed it. Added an **AST control** that builds the alias map from
  every Import/ImportFrom node and resolves every Name and Attribute through it before testing
  — attribute access, not only calls, because `os.environ["TZ"]` is a Subscript. 24 known
  bypasses are asserted caught, 9 legitimate spellings asserted not-caught, and the guard's
  `os.stat`/`os.environ` exemption is asserted narrow. The regex is kept as a cheap second net;
  nothing was deleted.
- **[minor] `is_fragmented` was blind to direction.** It sorted extents before testing
  adjacency, so two TOUCHING runs in reverse logical order reported `fragmented=False` —
  physically contiguous, reassembles backwards, wrong hash, labelled signature-only. Latent,
  not live (FRAG-07 has a 24-cluster separation), but FRAG-07's whole reason for existing is
  direction. Direction is now tested first, and the reversed-adjacent pair is a third case in
  `test_the_two_definitions_actually_differ`.
- **[minor] The max_gap convention was implied, not published.** FRAG-03 sits exactly on the
  128-cluster budget, so `gap < budget` instead of `gap <= budget` silently costs one file and
  makes the demo's attribution false. The manifest now carries `max_gap_clusters: 128` and
  `max_gap_is_inclusive: true` for the carver to read, and two tests assert that
  `disposal_certificate.pdf` is the only file on the boundary and is counted recoverable.
- **[minor] The residue's false-positive floor is now measured and published.** 3-byte magics
  do occur by chance in the SHAKE residue; 4-byte ones did not.
  `residue_signature_false_positives` is counted on the finished image at build time:
  **JPEG 8, GZIP 13, BZ2 11, PNG 0, PDF 0, ZIP 0, MP4 0, SQLITE 0**, independently reproduced
  in the test. (The `~0.03 per magic` note the finding quoted does not exist in `plan.py`;
  `grep -n "0.03\|by chance\|probability" fixtures/plan.py` returns nothing. The substance was
  right, the citation was not, so the measurement was added rather than a note corrected.)
- **[minor] 10 of the 48 red-team rows were settled by one blanket macOS clause**, leaving the
  device allowlist, the environment factor, the alias rule, the root-backing-disk rule and the
  typed confirmation — CLAUDE.md rule 4's disqualifying-defect area — with no test that could
  fail. `authorize(..., _platform=)` is a documented test-only seam that bypasses **D0 and only
  D0**; 13 new tests reach D1..D6 individually, each asserting its own DENY_ code, plus a
  positive control (ALLOW_DEVICE on /dev/null, decision only, no descriptor), a test that the
  seam does not reach the file rules (/.vol still refused) and one that it defaults to the real
  platform.
- **[minor] `make clean-fixtures` claimed removals it had not made.** It now counts what
  existed: "removed N of 2 generated files" or "nothing to remove under <OUT>".
- **Determinism hardening found while re-measuring.** Zeroing the deleted dirents moved the
  whole-image entropy to 7.061690499603866, whose distance to the 6-decimal rounding boundary
  is **3.96e-10** — three orders tighter than the previous build's 2.6e-7.
  `shannon_bits_per_byte` now uses `math.fsum` (exactly rounded, order-independent) over a
