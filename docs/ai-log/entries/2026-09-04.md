## Session 11 · The desktop shell

**Asked.** Build the Tauri shell — the frontend inbuilt, a native binary.

**Produced.** desktop/, a standalone Tauri v2 crate deliberately outside the core
workspace so the webview tree never enters the engine's lockfile. It bundles exactly the
two pages (stage.py refuses a page whose payload block is missing), exposes no IPC, and
its CSP starts at default-src 'none'. `make app` builds SENTINELWIPE.app: **4.8 MB
measured**, adhoc-signed, zero network-related libraries in `otool -L`. The pages passed a
CSP pre-flight under the exact policy before the shell was ever built, and the instrument's
wordmark now links back to the film because a native window has no browser chrome.

**What I verified, and what I could not.** The app runs stable with a 1710x1073 content
window and 398 accessibility nodes where a failed load yields a handful; compile-time
embedding hard-fails on missing dist files; the asset key /approach.html is in the binary.
What I did NOT verify: the rendered pixels. screencapture needs Screen Recording
permission, the AX value tree is closed to WKWebView without enhanced-UI mode, and two
brotli scans of the embedded assets failed — the second because brotli.decompress refuses
trailing garbage, so the scan was structurally incapable of succeeding at the true offset,
a defect in my probe I only saw after reading its suspicious 2-second runtime. The window
is open on the operator's screen; the operator is the final verifier.

**A smaller lesson repeated.** My first refresh-pipeline runner treated the post-wipe
carve's exit 1 as failure. The engine says it itself: "no candidate reached the gate.
exit 1 — a complete report, not an error." On the post-wipe pass, admitting zero is the
result the demo exists to produce.

## 04:20 · Surface 0 — the entry, ui/index.html

**Asked.** Build the demo entry surface: the door in front of the instrument and
the film. Cold open on the lying drive and the arithmetic that caught it; the
post-wipe carve held empty; the honesty surfaces (replay marker, ceiling and
recall kept apart, the weakest admission, the coverage limit); one keyboard path;
1366x768; zero network; file:// with no build step.

**Produced.** `ui/index.html`, one self-contained file, four acts on one stage.
`ui/tokens.css` is embedded verbatim and `ui/payload.json` in the same compact
form `ui/inline.py` writes, so the same drift check reads the same primitives and
the same payload here as in the other two pages — verified by running inline.py's
own `primitives()` and `OPEN_RE` against all three: 86 primitives, zero drift,
payload current in each.

Every figure is bound by `data-num="<payload path>"` with the path printed beside
it, so the screen can be read against `docs/frontend_contract.md` without opening
the script. 54 distinct fields, all 54 in the contract's 328. Six numerals are
typed in markup and none is a measurement: the act numbers 01-04, the `4` in
`MP4`, and the `256` in `SHA-256`. Five values are divided or added in the page
with the operands next to the result — the derived floor (BigInt, because
`work_bytes x probe_elapsed_ns` overruns IEEE-754 integer range, matching
build_payload.py's truncating `//`), the 431,059.458x quotient, the 30 rejected,
the reachability partition summing to 40, and 1,024/524,288.

The replay marker is permanent in the rack: it names `run.run_id` and prints a
SHA-256 of the embedded payload computed in the page by a hand-written SHA-256
(no WebCrypto, so no secure-context dependency on file://). It agrees with
`shasum -a 256 ui/payload.json`: `7c46b3d5f15ea080b8989294bc073ad3f7ebdeab240bd5d5a48ddcd76b77ad07`.

Two things the brief asked for are not in the payload and are rendered absent
rather than typed in. The ZIP at offset 1,228,603 scoring 0.7550 does not exist
in `carve.records`; the page runs the four checks that would have to be non-zero
for it to exist and prints all four as zero. `carve.margin.lowest_admitted` is
0.900000 and every admitted record has `sha256_matches` true, so this payload
carries no false positive at all. What it does carry is a genuinely thin margin,
and that is on the screen instead: `carve.margin.binds` is `structural_headroom`
at 0.035714, not the 0.100000 gate headroom.

Also: `ui/instrument.html` and `ui/approach.html` each got a 44px "Entry" link and
an Escape handler back to `ui/index.html`, guarded so it never fires while the
operator is typing the destructive-confirmation string. Nothing else in either
file was touched; both still parse, still carry their payload block, still pass
the drift check, and render in Chrome with no console errors.

Verified in Chrome at 1366x768 from `file://`, both `prefers-reduced-motion`
states: load 203 ms, zero console errors, zero non-`file:` requests, zero vertical
and zero horizontal scroll on all four acts, thesis 68 px against 17 px body
(exactly 4x), replay marker visible on every act with no interaction, Escape back
to the cold open in 8-18 ms.

**Unsure.** Four things.

1. **`loop.recall_before` is a literal.** `ui/build_payload.py` writes
   `"recall_before": 28` as source code, not out of a run artifact, while
   `carve.ground_truth.recall_measured` in the same payload is `false` and
   `demonstrated_recall` is `null`. It is a payload field, so the page binds it,
   but it is the one figure whose provenance chain ends in Python rather than in
   a measurement, and rule 2 is stricter than that. I put the admission on the
   screen next to the number rather than hiding it, but the real fix is upstream:
   either carve_pre.json grows a measured recall field or the number comes off
   the slide. A jury that reads build_payload.py will find this in a minute.
2. **`ui/index.html` is outside inline.py's `PAGES`.** `PAGES` is a two-element
   tuple and the file is off limits, so index.html's token block and payload
   block are copies that nothing regenerates. They are byte-identical today and I
   verified that with inline.py's own functions, but the next `make ui` updates
   two pages and not three. Adding `"ui/index.html"` to that tuple is the whole
   fix and it is one word.
3. **Only tested in Chrome 1366x768.** Not on the projector, not in Safari or
   Firefox, and the SHA-256 fallback path (`typeof BigInt !== "function"`) has
   never executed because every browser I can reach has BigInt.
4. **The colour budget is argued, not measured.** I counted nine values per act
   by reading the stylesheet, not by sampling rendered pixels: ti-100/95/90/00/20
   /40, au-30/40, and one signal per act, with content-quaternary deliberately
   unused. No tool checks this and one careless later edit breaks it silently.

Six beats, one `Space` apart: the lie, the medium, the carve, the sanitize, the
carve again, the limit. The opening screen carried thirteen figures and now
carries one at 175 px — `431,059.458×`, divided in the page — with four more in

one that remains is still bound by `data-num="<payload path>"`. Nothing was

The new asset is the medium itself. `device.total_sectors` is 524,288, which is
exactly 1024 × 512, so the canvas backing store is one pixel per sector with
nothing aggregated away. It is drawn from two payload fields and no third:
`carve.records[].offset`/`.length` place the object extents, and `frames[].hx`
supplies 12,544 bytes of the pattern the wipe actually wrote — so the post-wipe
static is made of the real overwrite stream rather than `Math.random()`. The
sweep replays the 49 recorded frames at their own `first_sector`/`sector_count`,
each frame's `entropy_sample` setting its brightness. The film grain over the
page is generated from the same byte pool, which is also how the file ends up
with no URL of any kind in it — the first cut used an SVG `feTurbulence` data
URI and the XML namespace `http://www.w3.org/2000/svg` tripped the air-gap grep.

Verified in Chrome at 1366×768 from `file://`, both motion settings: zero
console errors, zero non-`file:` requests, and zero horizontal or vertical
overflow on all six beats. `ui/inline.py` still passes on the other two pages,
86 primitives, zero drift.
