## Session 11 · The desktop shell

**Asked.** Build the Tauri shell — the frontend inbuilt, a native binary.

**Produced.** desktop/, a standalone Tauri v2 crate deliberately outside the core
workspace so the webview tree never enters the engine's lockfile. It bundles exactly the
two pages (stage.py refuses a page whose payload block is missing), exposes no IPC, and
its CSP starts at default-src 'none'. `make app` builds SENTINELWIPE.app: **4.8 MB
measured**, adhoc-signed, zero network-related libraries in `otool -L`. The pages passed a
CSP pre-flight under the exact policy before the shell was ever built, and the instrument's
wordmark now links back to the film because a native window has no browser chrome.

**What I verified, and what I could not.** The app runs stable with a 1710x1073 content
window and 398 accessibility nodes where a failed load yields a handful; compile-time
embedding hard-fails on missing dist files; the asset key /approach.html is in the binary.
What I did NOT verify: the rendered pixels. screencapture needs Screen Recording
permission, the AX value tree is closed to WKWebView without enhanced-UI mode, and two
brotli scans of the embedded assets failed — the second because brotli.decompress refuses
trailing garbage, so the scan was structurally incapable of succeeding at the true offset,
a defect in my probe I only saw after reading its suspicious 2-second runtime. The window
is open on the operator's screen; the operator is the final verifier.

**A smaller lesson repeated.** My first refresh-pipeline runner treated the post-wipe
carve's exit 1 as failure. The engine says it itself: "no candidate reached the gate.
exit 1 — a complete report, not an error." On the post-wipe pass, admitting zero is the
result the demo exists to produce.

## Session 11b · Repairing main after the Windows-parity push

**Found.** Commit 2429034 landed on main mid-session from outside this session, and main
stopped compiling: guard.rs was renamed to guard/unix.rs but reads ITS OWN SOURCE via
include_str!("guard.rs") — the conformance test that greps itself for the race-test
function names — and the self-reference did not survive the rename. The commit cannot have
been built before it was pushed. Separately, the new fixtures/guard package façade dropped
28 decision-code constants (a star-import honours __all__; the old callers accessed module
attributes, where __all__ never applies): 77 pytest failures.

**My first fix made the second bug subtler.** A vars() hoist restored the names but as
COPIES, so monkeypatch.setattr(fixtures.guard, "authorize", ...) patched the façade while
open_authorized kept calling the backend's own global — the five race-attack tests could
no longer install their probe and reported DID NOT RAISE. The only façade that preserves
the pre-split semantics exactly is sys.modules["fixtures.guard"] = backend, with __path__
carried over so fixtures.guard.windows stays importable. Aliased, all 8 residual failures
cleared in one stroke, including the path-decay ones fixed alongside (the vectors runner
read guard.rs; the write-detector's vacuity control read fixtures/guard.py; the exemption
list named a file that no longer exists).

**One flaky-under-load test, measured and left alone.** telemetry's
the_default_period_clears_the_twenty_hertz_floor failed once at max gap 57.84 ms against
its 50 ms floor while the full suite competed for cores, then passed 5 of 5 idle. It is an
honest real-time measurement and blunting it would gut it; noted instead: do not run the
suite under heavy parallel load and read a single timing failure as a regression.

**And my own recurring defect, third occurrence.** A pipeline exit swallowed a red suite
again ("exit=0" captured from tail while 77 tests failed; earlier the same shape hid a
tree that did not compile). Recorded to memory: the exit code comes from the command,
never from the pipe.

Final: cargo 485 passed, pytest 262 passed / 24 skipped (the Windows backend on macOS),
MAKE_EXIT=0 captured from make itself. Fixture sha256 unchanged.
